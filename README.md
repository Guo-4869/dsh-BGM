# dsh-bgm

给 [DeepSeek Harness](https://github.com/deepseek-ai)（DSH）用的**常驻背景音乐**插件：把音频丢进一个文件夹，进入 Harness 后就一直放着，按文件名轮播，右下角/左下角一个小胶囊可以暂停、切歌、调音量、拖着走。

- 轮播整个 `~/.dsh/bgm/` 文件夹，一轮结束自动重扫（加歌/删歌不用重启）
- ⏮ ⏸ ⏭、静音、音量滑杆、当前曲目
- **长按约 0.4 秒可拖动**，松手记住位置；位置、音量、静音都跨重启保留
- 片头动画（dsh-boot-animation）在播时自动让路，不会两段声音叠在一起
- 窗口最小化自动暂停，切回来**从原位置继续**（不回到开头）

## 安装

桌面客户端（profile 为 `desktop`）：

```sh
dsh plugin --profile desktop add github:Guo-4869/dsh-BGM
```

或者在客户端里 **设置 → 插件** 的安装框里填 `github:Guo-4869/dsh-BGM`。

浏览器服务（`dsh web`，profile 为 `web`）：

```sh
dsh plugin --profile web add github:Guo-4869/dsh-BGM
```

装完**重启一次** DSH（bundle 层只在启动时装配），然后刷新页面。

> 仓库里提交了 `lib/` 构建产物，安装时**不编译任何东西**，不需要 `pnpm install`、也不会触发构建脚本授权。

## 使用

1. 把音频放进 `~/.dsh/bgm/`（Windows：`C:\Users\<你>\.dsh\bgm\`）
2. **点一下界面任意位置** —— 浏览器不允许无交互自动播放声音，这是解锁步骤
3. 胶囊出现在左下角：

| 控件 | 作用 |
|---|---|
| ⏮ / ⏭ | 上一首 / 下一首，首尾环绕；切歌会解除暂停 |
| ⏸ / ▶ | 暂停 / 继续，继续时接着播同一首的同一位置 |
| 🎵 / 🔇 | 静音开关 |
| 滑杆 | 音量 |
| 文字 | 当前曲目（带 `已暂停` / `已静音` 前缀） |

**长按 0.38 秒**胶囊即可拖动，按住时胶囊会轻微放大并出现投影；短按仍然是点按钮。音量滑杆上按下不会触发拖动。窗口变小后胶囊会被拉回可视区内。

## 支持的格式

`.mp3` `.m4a` `.aac` `.ogg` `.opus` `.wav` `.flac` `.webm`

能不能播最终取决于浏览器的解码器：**H.264/AAC 系的 mp4/m4a、mp3、ogg、wav 最稳**；flac 在部分平台可以。想要压缩体积或转换格式可以用 ffmpeg：

```sh
ffmpeg -i 原文件 -c:a aac -b:a 160k 目标.m4a
```

目录**不递归**，只扫 `~/.dsh/bgm/` 这一层（子文件夹会被忽略）。

## 配置

状态写在 `~/.dsh/bgm/.settings.json`，由宿主侧读写：

```json
{
  "volume": 0.4,
  "muted": false,
  "pos": { "x": 314, "y": 250 }
}
```

| 字段 | 含义 |
|---|---|
| `volume` | 0–1，越界会被钳制 |
| `muted` | 静音 |
| `pos` | 胶囊左上角坐标（视口像素）；`null` 表示用默认角落 |

**为什么存在宿主侧而不是 `localStorage`**：DSH 桌面版每次启动会绑一个新端口（`127.0.0.1:61742` → `…:53109` → …），而 `localStorage` 按 `host:port` 隔离——存那儿等于每次重启音量、静音、位置全部清零。写进文件才跨端口、跨重启有效。

## 工作原理

`lib/index.js`（宿主半边）只注册三条只读路由：

| 路由 | 作用 |
|---|---|
| `GET /dsh-bgm/list.json` | 目录与曲目清单（每次请求都重新扫描） |
| `GET /dsh-bgm/media/<file>` | 单个文件的字节流，支持 `Range`（`206`） |
| `GET` / `POST /dsh-bgm/settings.json` | 读取 / 保存设置，写入用临时文件 + rename 落盘 |

`lib/client.js`（浏览器半边）是纯 DOM 实现：一个脱离文档树的 `<audio>` 加一个固定定位的胶囊。没有 React、没有 slots，也不依赖任何 `@deepseek-ai/dsh-*` 包，因此不会被 DSH 的版本兼容闸门跳过。

三条行为规则：

1. **必须有一次用户手势**才能出声（浏览器硬性策略），所以首次 `pointerdown`/`keydown` 才是解锁点；
2. 片头动画在播时不抢声音，等它的浮层消失再起播（最多等 90 秒）；
3. **只有真正换曲才赋值 `audio.src`**——给 `src` 赋值会把播放位置归零，恢复播放时重新赋值就是"暂停后从头放"的成因。

## 测试

```sh
npm test
```

两套自测，都不需要联网、不需要 ffmpeg：

- `scripts/smoke.mjs`（25 项）：临时 `$DSH_HOME` 里手写两个 WAV 文件，起真实 HTTP 服务，验证列表、忽略非音频、全量 `200`、`Range` → `206` + `content-range`、分片与全量字节一致、目录穿越被拒、设置往返与越界钳制。
- `scripts/ui-smoke.mjs`（39 项）：用一个极小的 DOM 打桩把客户端插件挂载起来，真的点 ⏮ / ⏸ / ⏭、模拟长按拖动、验证"暂停恢复不重载"（`src` 赋值计数与 `currentTime` 断言）。

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 胶囊不出现 | 插件没加载。确认 `dsh plugin --profile <profile> list` 里有 `dsh-bgm`，并**完全重启** DSH |
| 有胶囊但没声音 | 还没点过界面（未解锁）；或静音；或系统音量 |
| 加了歌但列表没变 | 列表在播放启动和每轮结束时重扫；点 ⏸ → ▶ 或重新进入页面 |
| 拖动后位置没保住 | 检查 `~/.dsh/bgm/.settings.json` 是否有写权限（程序目录以外的原因） |
| 重启后设置全丢 | 说明读的是旧版本（`localStorage` 方案）；升级到 0.4.0+ |
